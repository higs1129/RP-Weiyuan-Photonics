# launch 会话的启动与关闭

0.3.10 起，关闭或隐藏浏览器页面不停止采集、守护、原生观察或已开启的激励。网页重新打开可接回现有采集，激励面板可停止仍在运行的输出。主动切换功能页、点击暂停/停止、关闭原生观察窗口仍执行各自原有的停止行为。

launch CMD 是实验会话的生命周期入口。应用以隐藏进程运行，持有 Windows Job Object，子后台自动归入同一个作业。应用监视真实启动进程句柄；关闭 CMD 后先拒绝新操作、取消采集/守护和激励续期，再核对后台实例令牌，关闭并读回 RP 输出，然后退出 PyRPL。没有激光器 TEC / LD 关闭动作。

退出最长等待 20 秒；若后台或连接启动卡住，到时只终止本次作业进程。应用崩溃也由 Windows 回收作业中的后台，不搜索或清理所有 Python 进程。异常强制退出不能证明 RP 寄存器输出已经关闭，日志明确记录这一点。断电、网络失联时同样不能承诺远程输出关闭。

浏览器由 CMD 侧打开，在仪器作业之外；不会因本次清理而结束用户浏览器。网页不再发送 pagehide/visibilitychange 停止命令，连续采集不再依赖浏览器五秒租约。激励续期由应用会话每两秒维持，后台原有十秒失联保护和单次 burst 自动结束保留。

`standalone/sessions/` 中保存本次访问地址和退出日志。隐藏后台退出完成前保持 session.lock，避免 CMD 已关闭但清理还未结束时更新环境。

通信程序启动前，公共库 0.2.34 通过现有 SSH 连接读取 RP 上 monitor_server 的 SHA256，与固定 PyRPL 包的候选文件比较。一致时直接启动；缺失、不同、无法校验或启动失败才使用原安装流程。同路径覆盖，不创建累积版本。FPGA 仍自动检查，必要时重新加载，因此首次上电连接仍可能需要一些时间。

开发验证均为离线替身和临时 Windows 进程；尚未用真实仪器计时或验证退出后的物理输出。
