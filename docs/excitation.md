# 时域观察：ASG1 激励与响应

版本 0.3.4，固定公共设备库 0.2.29。开发验证为离线验证，未用真实 RP 验证触发延时。

进入测量初始化、时域观察、频域观察自动开始连续显示；恢复扫频后也自动显示。暂停后保持暂停。进入页面不会打开 ASG1 输出。

时域观察中的“输出激励”可以选择连续或单次 burst。支持正弦、50% 方波、三角波、上升锯齿波、自定义归一化 JSON 波表。频率范围 1 Hz–1 MHz；幅度为 PyRPL 峰值 V，Vpp 为两倍幅度；|偏置| + 幅度不得超过 1 V。自定义单周期数组 2–16384 点、每点 [-1,1]，周期线性插值到 16384 点；频率指整张波表重复频率。Burst 限定 1–100000 周期且总长不超过 2 秒。

激励和观察独立控制。需要同步响应时，暂停观察，选择“ASG1 内部同步”，再连续运行或单次采集，随后发出激励。输出控制保持原有示波器设置；可以在等待触发期间发出激励。连续观察未收到 ASG1 触发时继续等待（每次有界等待超时后重武装，有采集空隙）。单次采集超时会提示未收到触发。已经结束的单次 burst 不会被事后采集重放，需要重新发送。

“发送时同步采集一帧”是可选的 burst 测试流程：暂停原连续观察，CH1=ASG1、CH2=IN2，等待预触发缓冲就绪后发送，保留完整帧。它不会反复发出 burst。未勾选时只输出，采集由下方观察控件决定。

“Burst · 周期重复”由 RP 硬件自动重复，独立设置包内频率 f、每包周期数 N、整包重复周期 T（相邻起点的间隔）。例如 1 kHz、5 周期、T=0.1 s：每包约 5 ms，间隔约 95 ms，每秒 10 包。要求 T ≥ N/f + 1 μs；间隔以 1 μs 量化，界面显示量化后的名义周期，不代表实测精度。点“开始周期 burst”后持续发包，点停止、切换功能页或后台租约超时停止。“连续波”则没有包间间隔。周期模式不启用“同步采集一帧”。包间保持停止相位附近电平（含偏置），正弦零偏置接近零，其他波形不保证为零。

观察选择“ASG1 内部同步”并连续运行，可不断刷新触发帧；选择自由采集可以看到波包在时间窗口中的变化。当前仍为分帧采集，不是无缝滚动记录，快速重复时可能跳过一些波包；内部 ASG 事件包含包内每周期回绕，尤其不能保证每帧都对齐整包第一个点。需要严格整包起点/每包无遗漏的测量时，需另外实现并验证专用包起点触发与采集流程。

CH1 的 ASG1 是内部数字波形，不是 OUT1 模拟端口实测。t=0 是 FPGA 内部 ASG1 事件；当前固件的事件可能对应波表回绕，不能保证等于 burst 首周期起点。若需要精确物理起点、线路延时或首周期响应，需将 OUT1 回接输入验证并标定。未添加 PID1 方波转换、第三个采集通道、外部 TTL 同步输出或 HV 标度换算。

不修改 ASG0、PID0 或 OUT2；如果其他模块已路由到 OUT1，拒绝开启激励。连续输出明确点击开启，手动停止、切换功能页会停止；应用会话维持心跳，后台心跳丢失约 10 秒后关闭。关闭/隐藏网页不停止输出，关闭 launch CMD 停止本次实验及后台。Burst 硬件按周期数结束，后台随后关闭路由。暂停采集本身不会停止激励。硬件失联时无法保证已关闭，界面会提示未确认。

升级后旧的 PyRPL 后台不会自动获得接口。在未采集、未锁定时从“仪器连接”重启 RP 后台，然后再测试。无需改动原有个人配置。

0.3.4 / 公共库 0.2.29 修正 Python 3.10 下未捕获 asyncio.TimeoutError 的问题。ASG1 连续观察超过单帧 20 秒等待上限而没有触发时，保留当前帧并重新等待，不报采集中断；单次采集仍会结束等待并提示超时。真实通信错误、已触发后卡住或非 ASG1 模式超时仍报告错误。旧后台没有此修复时会明确提示重启。重新武装存在短暂采集空隙，非无缝记录。

0.3.2 / 公共库 0.2.27 修复有限 burst 不结束及静音后内部事件仍持续的问题：软件只发出一次触发，关闭附加重复，结束后复位内部发生器。旧后台即使支持激励接口也必须重启，新界面会阻止使用未修复后台发出激励。等待下一次触发时保留上次画面并显示等待状态，不将正常等待标为数据过期错误。100 kHz × 50 周期的波包只有 0.5 ms，若要分辨各周期，还需要缩短采集时长或放大横轴；单纯放大不能恢复采样时丢失的细节。

## 离线验证记录

- 16 项公共驱动检查：波形、参数范围、burst 周期数、一次触发及停止内部发生器、先等待后发送、取消/租约、端口冲突及失败清理；周期重复寄存器、间隔换算、其他控制位保留、参数拒绝及读回失败清理。
- 10 项安装后接口检查：独立激励不占用采集锁、不暂停原观察、触发路由、未触发等待与保留帧、HTTP JSON 传递、旧后台拒绝启动、周期模式能力及触发等待修复版本检查。
- 6 项真实 PyRPL wait 离线检查（源码及安装后 wheel 均通过）：重复计时超时、HTTP 分类、通信超时不误判、即时模式超时、触发后卡住、已完成任务异常；使用本地 Future，不连接设备。
- 按固定 FPGA RTL 编写的逐时钟离线模型复现旧参数导致持续输出，验证修复参数下 1/2/5/50/100 周期及连续/复位行为。
- 周期状态机模型核对 1/5/50 周期多包输出、名义间隔和中途复位；浏览器核对周期输入、无效周期/旧后台拦截、只发送一次启动请求、连续观察不被打断及离页停止。
- 原有 9 项失锁重锁检查、11 项网络/凭据/量程检查通过。
- 浏览器检查：三个页面自动连续、恢复扫频自动连续、手动暂停、连续/burst 激励独立控制、快速切页及迟到返回取消；1280、1366、1920 宽度下默认波形可见且无横向溢出。
- 干净源码构建公共库 wheel，确认不含已移出的旧微源控制台。离线依赖资源校验及独立 Python 环境安装、导入、Qt 探测、pip check 通过。

以上不等于实机输出/时序验收；现场诊断只读状态及时间戳，开发验证未发出真实激励或改变实验状态。

## 0.3.5：自动时间窗和完整帧观察

burst 模式按频率和每包周期数自动匹配时间窗，t=0 仍在中间。例：400 kHz × 50 周期为 125 μs/包，采集窗 524.288 μs，31.25 MSa/s，约 78 点/周期。单次/周期 burst 均使用此单包响应窗口；整包重复周期独立控制，不用网页定时发包。默认勾选“按 burst 自动匹配采集时长”；观察较慢响应时可取消勾选，再手动加长采集设置中的时长。输出始终需点击。

点连续运行或单次采集会应用当前 burst 时间窗；运行中修改激励参数后点击发送，会先按新窗口重新准备采集。单次 burst + ASG1 同步等待武装确认；勾选同步采集一帧仍先武装后发包。没有运行观察时，单独输出不会启动采集。时间轴缩放不改变采样时间窗。

ASG1 同步连续观察、单次采集及暂停后的完整 scope 帧都逐点绘制，不做网页二次抽样。界面显示实际采样率及全分辨率状态。像素有限时密集曲线仍可能重叠，请放大；这不代表丢点。硬件 decimation、帧间空隙仍存在。

连接时核对后台身份；匹配复用，空闲时自动更换旧后台。采集、输出、守护在用或状态无法读回时保留现场并提示。手动重启按钮仍为明确的恢复操作。更新应用后需关闭旧平台进程并运行 update.cmd；不需每次手动重启后台。没有进行真实设备验收。
